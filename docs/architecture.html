Factory Inventory Management System

A full-stack demo: a Vue 3 single-page app talking to a read-only FastAPI service over JSON, backed by seven flat files loaded into memory at startup. No database, no authentication, no persistence — every request filters Python lists in process.

System architecture

Three layers, one process each for the front end and the API. Every arrow crosses a real boundary: the browser reaches the API over HTTP, and the API reaches its data through a module import that happens exactly once.

Data flow — one filter change, end to end

The filter bar is the spine of the app: four controls drive every view. Filter state is a module-level singleton, so changing a filter in one view changes it everywhere.

  1. User changes a control in FilterBar.vue

    Four dimensions: time period, location (warehouse), category, order status.

  2. State lands in a shared composable — useFilters.js

    The four refs live at module scope, outside the exported function, so every component that calls useFilters() reads and writes the same objects. This is a singleton store by construction, not by convention.

  3. The view requests data through api.js

    Views hold raw responses in refs and derive everything displayed via computed.

  4. Filters become query params

    URLSearchParams is built one key at a time, and the sentinel value 'all' is dropped rather than sent — so "no filter" is an absent param, not an empty one.

  5. HTTP crosses to the API — GET http://localhost:8001/api/…

    The base URL is hard-coded in api.js; there is no environment configuration.

  6. FastAPI filters in Python

    apply_filters() chains list comprehensions over the in-memory lists — case-insensitive on category and status, exact on warehouse. filter_by_month() matches either a month (2025-03) or a quarter, expanded through QUARTER_MAP. Filtering rebinds a local name each step, so the source lists are never mutated.

  7. Pydantic validates the response

    Where response_model is declared, the payload shape is enforced on the way out.

  8. The view re-derives and re-renders

    Raw data in refs, everything else computed — KPI cards, SVG charts and tables all recompute from the same source.

Observations from the walkthrough

Each item below was read out of the source, not inferred from the running app. Several look like deliberate gaps left for the workshop rather than accidents.

Six client API methods have no server route Critical

api.js exposes getTasks, createTask, deleteTask, toggleTask, createPurchaseOrder and getPurchaseOrderByBacklogItem. None of the six paths exist in main.py. App.vue calls the four task methods on mount, so every page load logs a real 404 /api/tasks server-side — visible in /tmp/inventory-backend.log.

The purchase-order feature is scaffolded on both sides but never wired Warning

The back end declares PurchaseOrder and CreatePurchaseOrderRequest models that no route references, imports a purchase_orders list that is always empty (purchase_orders.json is []), and computes has_purchase_order on every backlog item — a flag that can therefore only ever be false. The client half is equally inert: its two purchase-order methods are defined and called by nothing.

Quarter filtering is hard-coded to 2025 Warning

QUARTER_MAP enumerates only Q1-2025 through Q4-2025, and /api/reports/quarterly repeats the same year as a chain of if branches. Any order dated outside 2025 is silently dropped from quarterly reporting rather than reported as unclassified.

Seven of thirteen /api routes return untyped dictionaries Serious

The dashboard summary, all four spending routes and both report routes omit response_model. Their shape is whatever the function happens to build, so it is absent from the OpenAPI schema at /docs and unchecked at runtime — exactly the endpoints whose payloads are computed rather than passed through.

Permissive CORS and no authentication Serious

allow_origins=["*"] is combined with allow_credentials=True, and there is no auth layer at all — useAuth.js is a hard-coded mock user, not a session. Fine for a local demo, disqualifying for anything reachable.

views/Backlog.vue is dead code Note

152 lines, absent from the router and imported by no component. Backlog data does reach the UI, but through components/BacklogDetailModal.vue opened from the dashboard — a different file with a similar name.

Backend test coverage is real Good

Forty tests across three files exercise the endpoints through FastAPI's TestClient — dashboard aggregates, inventory filtering, and the remaining routes. Run with cd tests && uv run pytest backend/ -v.
